nano-ontoprompt 本地开发环境

在原始源码基础上，为 Windows 二开搭建的“混合模式”开发环境说明

1. 整体思路

原项目的 docker-compose.v2.yml 会把前后端也放进容器。二开时这样不方便：断点调试要额外配置远程调试，Windows 挂载目录的热更新不稳定，新增依赖要重新 build 镜像。所以这里改成：

DOCKER · docker-compose.dev.yml

基础设施

  • PostgreSQL 16 — localhost:5432
  • Redis 7 — localhost:6379
  • Neo4j 5.20 — 7474（浏览器）/ 7687（bolt）
  • MinIO — 9000（API）/ 9001（控制台）
  • ChromaDB — localhost:8001
宿主机 · VS Code

应用本身

  • 后端 FastAPI — localhost:8000（backend/.venv）
  • 前端 Vite — localhost:5173，/api 代理到 8000
  • Celery worker — 按需启动
  • 断点调试、热更新、IDE 补全都直接可用

2. 做了哪些改动

文件是否入库作用
docker-compose.dev.yml是新增。只包含 5 个基础服务，项目名 ontoprompt-dev，数据卷和原 compose 相互独立。
backend/.env.dev.example是新增。本地开发配置模板，所有服务地址都改成 localhost。
backend/.env否由上面的模板复制而来，后端实际读取的配置，放只属于本机的值（比如改过的密码）。大模型的 API Key 不在这里填，要在网页的 Models 页面添加。
.vscode/launch.json是调试配置：后端、Celery、前端，以及一键启动全栈的组合配置。
scripts/dev-setup.ps1是一键准备环境的脚本，按 F5 时自动运行，详见第 4 节。
.vscode/tasks.json是任务 dev: setup（运行上面的脚本），以及管理 Docker 服务的 infra: up / down / logs。
.vscode/settings.json是把 Python 解释器指向 backend/.venv。
.gitignore是原规则忽略整个 .vscode/，改为只放行上面三个共享配置；另外补充了 backend/uploads/ 和 env 模板的例外规则。
backend/.venv、frontend/node_modules否依赖目录，已被忽略。

业务源码一行都没有改。

3. 配置过程中遇到的坑

坑 1：Docker Hub 上的 minio/minio 已拉取不到。 报错 pull access denied，还会连带中断其他镜像的拉取。解决：改用官方镜像地址 quay.io/minio/minio:latest。原来的 docker-compose.v2.yml 也有同样的问题，全量部署前需要一起改。
坑 2：.env 里写中文，Windows 上后端直接启动不了。 slowapi（通过 starlette Config）会用系统默认编码 GBK 读取 .env，遇到 UTF-8 中文就报 UnicodeDecodeError。解决：env 文件保持纯 ASCII，调试配置里再加上 PYTHONUTF8=1 作为双保险。在命令行手动启动时，最好也设置这个环境变量。
坑 3：原 .env.example 里的 CHROMA_PORT=8001。 在 Docker 网络内部，ChromaDB 实际监听 8000，8001 只是映射到宿主机的端口。用原 compose 全量部署时后端会连不上 ChromaDB；本地混合模式走 localhost:8001，正好没有这个问题。
已知但不影响运行： 启动时 Neo4j 会报一条索引创建失败的警告。原因是源码 backend/app/services/v2/graph/index_setup.py 里有一条 FOR (n) 索引语句没写节点标签，Neo4j 5 不支持这种写法。这是上游代码本身的问题，和环境配置无关。

4. 日常使用

方式 A：VS Code 一键启动（推荐，新电脑也一样）

只需要自己装好 Docker Desktop、Python 3.11+、Node 18+，然后：

  1. 打开 Docker Desktop，等它启动完成。
  2. VS Code 左侧进入“运行和调试”，选 Full stack (Backend + Frontend)，按 F5。
  3. 打开 http://localhost:5173，用 admin / admin123 登录。

按 F5 时会先运行 scripts/dev-setup.ps1，它依次做这些事，已经做过的步骤会自动跳过：

  1. 检查 Docker、Node、Python 是否安装，Docker Desktop 是否在运行，缺什么就提示安装命令。
  2. 如果没有 backend/.env，从模板复制一份。已有的不会被覆盖。
  3. 创建 backend/.venv 并安装后端依赖。只在 requirements.txt 变化时重装。
  4. 安装前端依赖（npm ci）。只在 package-lock.json 变化时重装。
  5. 启动 Docker 服务，并等所有服务就绪后再启动后端，避免后端连不上数据库。

新电脑第一次按 F5 要装依赖，需要几分钟；之后每次只要一两秒。同事 git pull 到新依赖后，下次按 F5 也会自动补装。

注意： 需要重装前端依赖时，如果前端开发服务器还在运行，脚本会拒绝执行并提示先停止（Shift+F5）。原因是运行中的 Vite 会锁住依赖里的文件，这时强行重装会把 node_modules 删到一半。

方式 B：命令行

# 1. 基础服务
docker compose -f docker-compose.dev.yml up -d

# 2. 后端（PowerShell）
cd backend
$env:PYTHONUTF8="1"
.venv\Scripts\python -m uvicorn app.main:app --reload --port 8000

# 3. 前端（另开一个终端）
cd frontend
npm run dev

# 可选：Celery worker（Windows 上必须加 --pool=solo）
cd backend
.venv\Scripts\python -m celery -A app.tasks.extraction worker --loglevel=info --pool=solo

常用命令

目的命令
停止基础服务（保留数据）docker compose -f docker-compose.dev.yml down
清空所有数据重来docker compose -f docker-compose.dev.yml down -v
查看服务日志docker compose -f docker-compose.dev.yml logs -f
API 文档http://localhost:8000/docs
Neo4j 浏览器http://localhost:7474（neo4j / ontoprompt123）
MinIO 控制台http://localhost:9001（minioadmin / minioadmin）
新增 Python 依赖backend\.venv\Scripts\pip install xxx，然后写入 requirements.txt
数据库迁移在 backend 目录执行 .venv\Scripts\alembic upgrade head（后端启动时也会自动执行）

不想开 Docker 时

把 backend/.env 里的 DATABASE_URL 改成 sqlite:///./ontoprompt.db 即可。Neo4j、MinIO、ChromaDB、Redis 连不上时，项目会自动退回到 SQLite 图存储、本地文件存储和同步执行。
